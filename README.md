# **graphics engine**

## **О чем?**
Программный рендеринг на языке С,  
созданный для быстрой работы на слабых\старых процессорах

### Зачем создан?
Для создания симуляций и игр с высокой производительностью на слабых процессорах  
Создан чтобы дать полный доступ над управлением ресурсов разработчику

### Изменения
Этот файл будет редактироваться если что то будет изменено в проекте  
так как идет активное развитие этого проекта,  
в этот файл часто будут записываться дополнения и новые функции  

Можно писать о желаемых изменениях в Issues

### Ошибки
Сообщить об ошибках и багах можно в Issues

## **Совместимость**
Работает на любом процессоре

## **Архитектура проекта**
### Способ компиляции и запуска
Для компиляции проекта можно использовать build систему ***make*** командой ```make```  
так и напрямую обращаться к компилятору  

Так как проект использует библиотеку **OpenMP** для распределения нагрузки по ядрам,  
то для компиляции должен быть флаг ```-fopenmp```  

Для максимальной скорсти приведенна таблица рекомендуемых флагов ускорения:

| Флаг | Скорость сборки | Скорость приложения | Ошибки |
| :--- | :-------------- | :------------------ | :----- |
| -s   | не меняется     |         не меняется |    нет |
| -Ofast | ниже | очень быстрое | очень редко, почти нет |
| -flto | чуть медленней | чуть быстрее | нет |

*[Сайт, с которого бралась информация](https://gcc.gnu.org/onlinedocs/)*  

Также для компиляции должен быть флаг ```-lm```, так как используются функции из ```<math.h>```  

***На разных системах используйте разные команды компиляции  
Так как изначально проект создавался на Гну Линукс и команды компиляции написанны под нее***

На выходе должен скомпилироваться исполняемый файл под вашу систему который можно запустить

### Математика и функции отрисовки
Все основные математические функции находятся в файле *core_2d.h*  
Для отрисовки геометрических объектов в наименованиях функций используется префикс ***draw***  

Цвет хранится в формате ***AARRGGBB*** c типом данных ```unsigned int``` или ```uint32_t```  

Функции в названиях которых есть префикс ***glass***  
могут использовать указатель для буфера закрашенных пикселей,  
чтобы не зарисовывать одни и теже пиксели

Этот код создает такой буфер:
```c
uint8_t *fb = calloc(sizeof(uint8_t), SCREEN_WIDTH * SCREEN_HEIGHT);
```

После отрисовки прозрачного многополигонального объекта  
нужно обнулить буффер

```c
memset(fb, 0, SCREEN_WIDTH * SCREEN_HEIGHT * sizeof(uint8_t));
```

**Важно!** При обработке выхода из программы нужно освободить занятую память  

```c
free(fb);
```

Функции в названиях которых есть префикс ***refraction***  
могут использовать указатель для буфера пикселей,  
чтобы не зависеть от прошлого состояния кадра

Этот код создает такой буфер выровненный по 32 бита в памяти дл оптимизации под AVX2:
```c
uint32_t *framebuffer_2 = (uint32_t*)aligned_alloc(32, (SCREEN_WIDTH * SCREEN_HEIGHT * sizeof(uint32_t) + 31) & ~31);
```

После отрисовки прозрачного многополигонального объекта  
нужно копировать буффер в кадр

```c
/* оптимизированный под AVX2 */
memcpy_avx_epi32(framebuffer, framebuffer_2, SCREEN_WIDTH * SCREEN_HEIGHT);

/* обычный */
memcpy(framebuffer, framebuffer_2, SCREEN_WIDTH * SCREEN_HEIGHT * sizeof(uint32_t));
```

Перед отрисовкой объекта нужно сделать тоже самое -^

**Важно!** При обработке выхода из программы нужно освободить занятую память  

```c
free(framebuffer_2);
```

### Некоторые функции в файле *core_2d.h*

- Для отрисовки некоторых геометрический фигур используется алгоритм Брезенхэма  

- Функция ```reciprocal()``` принимает число ***а*** типа float и возвращает 1 \ ***а***  
Это добавленно чтобы заменить тяжелую операцию деления на умножение

- ```min()``` и ```max()``` созданны для работы с числами типа int

- ```max_vector()``` и ```min_vector()``` в векторе типа float находит наибольшее\наименьшее число

- ```vector_add_scal()``` добавляет скаляр к каждому элементу вектора

- ```blend_pixels()``` смешивает цвет на основе альфа канала

- ```shum()``` зашумляет картинку в процентах от 0 до 100, чем меньше процент зашумление  
тем быстрее работает

- ```clear_screen()``` закрашивает буффер одним цветом, если нужно закрасить буффер в оттенках серого, 
то можно использовать функцию ```memset()```,  по скорости эти две функции идентичны,  
но лучше использовать ```clear_screen_avx()```, так как это дает очень сильный прирост скорости
    - *Совет:* отрисовку больших обьектов лучше перекладывать на AVX

- ```memcpy_avx_epi32()``` это аналог ```memcpy()```, но переписанную под AVX. Дает сильный прирост скорости

- ```draw_line_avx()``` и аналогичные функции для рисовании линий с помощью AVX инструкций  
предназначенны для рисовании только горизонтальных линий

- ```get_time_in_seconds()``` выдает время в секундах

- ```rotate_polygon()``` поворачивает точки, как минимум 2. От центра фигуры

- ```draw_polygon()``` и аналогичные функции рисует только правильные многоугольники

- ```draw_len_string()``` в эту функцию надо явно передовать количество символов,   
так как они будут печататься паралельно,  
лучше это использовать когда надо нарисовать больше 1000 символов

- ```init_poligon()``` эта функция создает правильный многоугольник

- Функции для рисования квадратов не умеют рисовать повернутые квадраты,  
для этого рисуйте квадраты с помощью треугольников

- ```init_rect()``` эта функция на основе левой верхней точки и длины с высотой  
расчитывает 3 точки для прямоугольника

- ```alpha_writer()``` эта функция вшивает в цвет информацию о прозрачности AА канала

### Для разработчиков проекта
- **Генеративный ИИ и LLM (большие языковые модели) запрещенны**  
Проект на поддерживает код написанный с помощью генеративных ИИ моделей включая, LLM`s  
За исключением можно использовать LLM's как Wiki, чтобы не искать функцию в документациях часами  

- ~~Clean code~~  
Свободный стиль (в рамках разумного). Главное — читаемость и соблюдение базовых правил хорошего тона

- Работа в **GIT**  
Каждый работает внутри своей ветки, не работая напрямую в ***main***. Слияне веток обговаривается

- Проект развивается независимо от фреймворков и библиотек для графики

- ~~C++~~  
Проект не использует С++ для максимальной скорости и прозрачности кода

- Некоторые разделы в Математике которые являются ядром проекта:  
Линейная Алгебра, Геометрия, Тригонометрия, Стереометрия, Вероятность и статистика,  
Компьютерная арифметика

- Разработчики проекта должы придерживаться идей о свободном програмном обеспечении
